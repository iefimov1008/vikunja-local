# EA-010 — UX-спецификация

**Редакция 0.1 · черновик для ревью владельцем · 6 ноября 2026.**
Подготовлено по явному поручению владельца. Документ не принят и не подтверждает готовность интеграции. Описывает целевое поведение; названия новых действий — предложения для ревью. Готовый UI Vikunja сохраняется. Порты, адреса и версия устанавливаемого экземпляра здесь не назначаются.

## 1. Три входа, один список задач

| Где | Для чего | Что пользователь получает |
| --- | --- | --- |
| Hermes → «Личные задачи ↗» | Перейти в готовую Vikunja | Свой список, создание, редактирование и завершение обычных задач |
| Внешний чат, включая Codex | Управлять теми же задачами текстом | Подтверждённый результат, ID и ссылка на фактическую задачу |
| Hermes → «Встречи» → предложение | Осознанно принять действие из обсуждения | Задачу в той же Vikunja и связь с исходной встречей |

«Личные задачи» открывает отдельную вкладку готовой Vikunja. «Встречи» остаются разделом расшифровок и предложений. Доска Development используется только для разработки этой интеграции; обычная личная задача её не запускает.

Базовое представление трекера — штатный список задач; штатную канбан-доску пользователь может выбрать самостоятельно. Свой набор колонок и копия трекера внутри Hermes не создаются. Наличие списка/канбана у продукта подтверждается [официальным обзором Vikunja](https://vikunja.io/features/); конкретные подписи и доступные функции установленной версии проверяются при реализации.

## 2. Ручная задача

1. Владелец открывает «Личные задачи ↗» и при необходимости входит в Vikunja.
2. Создаёт задачу в готовом UI, указывает название, описание и необязательный срок.
3. Открывает задачу, редактирует и завершает штатными средствами.
4. Та же задача находится через чат; её ID и состояние не меняются из-за смены канала.

Встреча не требуется. Пустой список показывается только после успешного чтения. Недоступность Mini, туннеля или отказ входа не подменяются сообщением «задач нет». Интеграционные команды чата используют явное поле срока: распознавание даты из названия в штатном Quick Add не считается подтверждённым сроком для чата или предложений.

## 3. Внешний чат

Пример синтетического запроса: «Добавь личную задачу: подготовить повестку к пятнице».

- Перед записью уточняются только сведения, без которых нельзя определить действие: неоднозначная дата, проект при нескольких подходящих, несколько найденных задач для изменения. Повторное общее разрешение на явно порученное создание не требуется.
- Успешный ответ: «Задача создана: <название>. Срок: <подтверждённая дата либо не задан>. №<полученный ID>. Открыть задачу». ID и ссылка подставляются только после проверки результата.
- Поиск без совпадений сообщает об этом. При нескольких совпадениях показываются названия, ID и сроки, после выбора изменяется ровно выбранная задача.
- Повтор доставленной команды возвращает прежний результат. Совпадение текста двух независимо созданных задач само по себе не означает дубль.
- Изменение и завершение подтверждаются фактическим актуальным состоянием. Недоступность не трактуется как удаление.

Относительная дата считается по Europe/Moscow и показывается пользователю абсолютной датой. Если смысл неясен, запись ожидает уточнения; неопределённый срок не угадывается. Технические request ID не требуют ручного ввода.

## 4. Принятие предложения встречи

В карточке уже видны название встречи, её дата/начало/окончание и часовой пояс, краткий контекст, действие и тип обязательства. Для чужого обязательства принадлежность задачи подтверждает владелец.

1. «Добавить в мои задачи» открывает подтверждение, ничего не записывая.
2. В подтверждении — редактируемое название и срок, контекст встречи и ссылка на источник. Срок пуст по умолчанию; подсказка из речи отдельно помечена как неподтверждённая.
3. Владелец подтверждает выбранный срок или его отсутствие. Кнопка «Принять и передать в Vikunja» доступна после проверки названия, срока и текущей версии предложения.
4. Во время отправки кнопка занята. Закрытие и повторное открытие карточки не запускают ещё одну передачу.
5. После подтверждённой записи видны «Передано в Vikunja», ID и ссылка. Из задачи доступна ссылка обратно на конкретное предложение и встречу.

В описание задачи попадают краткий контекст, название и время встречи и возвратная ссылка. Полная расшифровка не копируется. Дата встречи не становится сроком задачи. Отмена подтверждения, просмотр и отметка прочтения не означают принятие.

## 5. Состояния передачи и восстановление

| Наблюдаемое состояние | Текст и доступное действие | Что сохраняется |
| --- | --- | --- |
| Предложение не принято | «Добавить в мои задачи» | Нет личной задачи |
| Принятие сохранено, передача ещё не подтверждена | «Принято · передаём в Vikunja» | Решение владельца |
| Задача подтверждена | «Передано в Vikunja · Открыть задачу» | ID и обратная связь |
| Результат записи неизвестен | «Проверяем результат передачи»; «Проверить передачу» | Принятие и сведения об операции; повторный create недоступен |
| Нет доступа или сервис недоступен | Понятная причина и «Проверить подключение» | Решение и история; успех не заявляется |
| Задача создана, связь не сохранилась | «Задача найдена · восстанавливаем связь» | Используется тот же ID; задача не создаётся заново |
| Источник изменился до принятия | «Предложение обновилось · проверьте текущую версию» | Старые решения и версии |
| Связанная задача удалена либо недоступна | «Связанная задача недоступна» | История; нет автоматического повторного создания |

«Предложение принято», «передано в трекер» и «задача выполнена» — три разных факта. Отказ доставки не отменяет принятие. Статус выполнения читается из Vikunja; при недоступности последнее прочитанное значение явно помечается временем чтения и не выдаётся за текущее.

## 6. Доступность и компактный экран

Действия имеют текстовые названия, доступны с клавиатуры; цвет дополняет подпись состояния. Модальное окно получает фокус, имеет видимую отмену, закрывается Escape и возвращает фокус на исходное действие. Во время записи доступные действия не должны создавать повторную операцию. Длинные названия и ссылки переносятся; дата, источник и основное действие видны на узком экране. Ошибка остаётся рядом с действием и не стирает введённое название/срок.

С Mini и MacBook открывается один экземпляр и один ID. Адреса могут различаться из-за защищённого маршрута; конкретные рабочие ссылки проверяются по плану. При потере соединения показывается восстановление доступа, а не ложное сохранение.

## 7. Что подтверждается этим ревью

Владелец оценивает навигацию, границу принятия предложения, понятность трёх фактов и состояний ошибок, сроки и возвратные ссылки. Чтение и принятие двух UX-черновиков фиксирует только эту редакцию UX. Оно не означает готовность службы, приёмку ТЗ/DoR/UAT или разрешение публикации.

Для реализации/QA: ручной CRUD и чтение через чат; чат → UI; принятие синтетического предложения; неизвестный исход и потеря связи; повтор без дубля; пустой/неоднозначный срок; изменённый источник; отказ доступа; клавиатура и экран 390 px. Это будущие проверки, здесь они не выполнялись.
